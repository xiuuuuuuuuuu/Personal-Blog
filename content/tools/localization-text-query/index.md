## v0.1 安装与试用

发布日期：2026-09-28。已验证环境：Unity 2022.3.62f3、Unity UI 1.0.0、TextMeshPro 3.0.7。其他 Unity 版本尚未验证。

1. 下载 `LocalizationTextQuery-v0.1.zip` 并解压。
2. 打开公司 Unity 项目，在 Package Manager 确认已安装 **Unity UI** 和 **TextMeshPro**。若项目原本已使用这两类文本，通常已具备依赖。无论实际是否用了 TMP，本版都需要 TextMeshPro 包才能编译；不要求导入 TMP Examples。
3. 选择 **Assets → Import Package → Custom Package…**，选择压缩包里的 `LocalizationTextQuery-v0.1.unitypackage`，保持全部勾选并导入。也可以直接双击 unitypackage。
4. 等待编译完成，打开 **Tools → 多语言 → 查询有用文本**。本版无需 Unity CLI、Pipeline、Python、Excel 软件或公司多语言 SDK。
5. 初次试用先在 Hierarchy 选中一个 Canvas，扫描范围选“选中对象及子物体／选中资源”，点击“开始查询”。核对结果确实来自这个 Canvas，再扩大扫描范围。
6. 点击任意文案在右侧填写 Key／备注，保存人工记录，然后导出 Excel。C# 候选默认不勾选，核对后再收录。

窗口顶部显示 v0.1。列表预留 20 行高度；结果不足 20 条时仅显示实际条数。安装目录为 `Assets/Editor/LocalizationTextQuery`，不包含游戏场景、Prefab、公司 SDK 或样例项目。

工具文件都只在 Editor 使用，不进入游戏运行时。版本管理中可提交工具文件及其 `.meta`，以及项目产生的 `ProjectSettings/LocalizationTextQueryReview.json`。后者保存的是自己项目的人工整理结果，发布包不携带其他项目的记录。

### 常见问题

- **找不到菜单／红色编译错误**：先解决 Console 中最早的编译错误，确认 Unity UI、TMP 已安装且完整导入 Dependencies。不要只删某个 DLL 来绕过错误。
- **选了 Canvas2 却查了别处**：确认扫描范围是“选中对象及子物体／选中资源”，并在 Hierarchy 中选中 Canvas2 后重新查询。上次的结果不会随选择自动重扫。
- **选择 Canvas 后代码分析变灰**：这是预期行为；源码无法可靠按 Canvas 实例划分。要查代码赋值，请切换目录／场景模式。
- **某条文本没有进入 Excel 候选表**：检查是否勾选；代码候选、纯数字和默认占位文案默认不收录。完整位置表和 JSON 会保留原因。
- **同一句话出现很多次**：每个使用位置都会记录；翻译候选表按原文、Key、接入方式汇总。
- **扫描了场景还漏了运行时内容**：Resources、Addressables 或服务器动态加载的资源需要补选目录；服务器文本、配置表和任意函数返回值不会被执行或完整追踪。
- **Excel 改完译文后再次导出**：本版不会回读旧 Excel，必须另存翻译工作文件，避免覆盖已翻译内容。

### 更新、卸载与反馈

覆盖安装前保存人工记录。若曾手动拷贝本工具到别的位置，先确认不存在两份同名源码程序集。

卸载时在 Unity 的 Project 窗口删除 `Assets/Editor/LocalizationTextQuery` 文件夹；项目的 UI 组件不会被替换。人工整理文件可以保留，今后重装继续使用。使用说明位于 `Assets/Docs`，可自行保留。

## 使用步骤

1. 选择扫描范围，首次盘点建议用“指定目录内场景和 Prefab”，目录填 `Assets` 或实际 UI／玩法目录。多个目录用分号分隔。
2. 点击“开始查询”。普通旧版 Text、TMP 中包含文字的内容默认收录；代码中的文本赋值作为待确认候选。
3. 搜索原文、资源路径、层级或 Key。勾选“显示默认排除项”可以查看空文本、纯数字和默认占位文案等。
4. 点击文案查看依据，核对收录状态，填写接入方式、Key 和备注。点击“定位”选中已加载对象或其资源；代码候选会打开对应行。尚未加载的场景只定位场景资源，避免切换或保存当前场景。
5. 保存人工记录，再导出 Excel `.xlsx` 或完整 JSON。

结果列表随窗口高度伸展，预留至少 20 行的高度。点击文案后，详情显示在右侧，不再挤占列表高度。

扫描只读取组件，不转换 TMP、不挂载 SDK、不修改代码。重复扫描前和关闭窗口时会保存已修改的人工记录，也可以主动保存。

## 什么算“有用”

“有用”在第一版中的含义是：**来自可识别的文本显示位置，且包含可翻译文字；其余保留为人工候选。** 它不等同于“已在玩家实际流程中出现”。

| 来源 | 当前处理 |
| --- | --- |
| `UnityEngine.UI.Text` | 读取原文，保存对象位置、组件类型和启用状态 |
| `TextMeshProUGUI`、`TextMeshPro` | 读取原文，标记需要 TMP 迁移；不会进行转换 |
| `Dropdown`、`TMP_Dropdown` | 完全跳过组件、选项、绑定文字和子层级，不加入查询结果 |
| `InputField`、`TMP_InputField` | 完全跳过组件、输入内容、占位提示和子层级，不加入查询结果 |
| 未激活对象／禁用组件 | 保留并标明状态，避免漏掉弹窗、模板和隐藏页签 |
| C# | 使用 Roslyn 类型分析，只查 Text/TMP 的 `.text` 赋值及 TMP 的 `SetText` 调用，记录行号和表达式，默认不收录 |
| 普通字符串字段／ScriptableObject | 不单独扫描；变量实际出现在文本赋值右侧时，才尝试追踪其源码初始值 |

空白、纯数字、符号、只有标签或参数，以及 Unity 默认的 `New Text` / `New TextMeshPro Text` 会保留在完整报告里，默认不进入翻译清单。“仅中文”不是过滤规则，英文、日文等文字也会收集。

## 底层如何查找

第一条路径是读取组件。通过 `AssetDatabase.FindAssets` 找到场景／Prefab，再遍历 `GetComponentsInChildren(..., true)`，读取 `UnityEngine.UI.Text.text` 和 `TMPro.TMP_Text.text`。`true` 表示包含未激活对象。不会为了读取文案而运行游戏逻辑。

第二条路径是分析代码。利用工具随附的 Roslyn C# 分析库，把源码解析成语法树；按 Unity 当前 Player 程序集的源码、条件编译符号和依赖 DLL 建立类型信息，不生成或运行游戏程序集。

例如 `label.text = "领取奖励"`：先找到赋值节点，确认左侧属性确实属于 `UnityEngine.UI.Text` 或 `TMPro.TMP_Text`，再分析右侧。其它类自己的 `.text` 字段、日志、注释、未被使用的普通字符串字段不会因此成为候选。TMP 的 `SetText(...)` 同样检查真实的方法类型。

| 赋值右侧 | 当前处理 |
| --- | --- |
| `"领取奖励"` 或 `const` 字符串 | 读取常量值，包括 C# 转义后的真实换行和 Unicode |
| `rewardDescription` | 仅在这里追踪它的源码初始值，最多 6 层，检测循环；标记可能被运行时赋值或 Inspector 覆盖 |
| `"获得 " + count + " 金币"` | 提供建议模板 `获得 {0} 金币`，并保留参数表达式和完整原始代码 |
| `$"剩余 {seconds:0.0} 秒"` | 提供建议模板 `剩余 {0:0.0} 秒` |
| `condition ? "成功" : "失败"` | 两个分支分别记录为候选 |
| `string.Format("第 {0} 关", level)` | 读取格式字符串，保留参数表达式 |
| `score.ToString()` | 记录数值赋值位置，默认排除 |
| `GetServerMessage()`、未知属性等 | 不运行方法、不搜刮其参数里的字符串，保留位置并标记“来源待追踪” |

这是语法和类型分析，加有限的变量初始值追踪；不是完整的数据流、调用图或运行时追踪。字段初始值可能被 Inspector 或其它代码覆盖，本地变量也可能再次赋值，因而追踪结果只是候选，不能宣称是实际显示值。拼接或插值中的复杂参数表达式不会继续无限展开，需结合原始表达式人工复核。建议模板不自动作为公司 SDK 最终格式。

代码直接访问 `input.text`、`input.textComponent.text`、`dropdown.captionText.text` 等会排除；任意别名或运行时绑定的对象归属不保证自动识别。文本类存在于代码中，也不证明它已挂到所选场景。源码当前编译条件下未启用的 `#if` 分支不纳入本次扫描。

v0.1 导入包已自带 Roslyn 和配套依赖，位于 `Assets/Editor/LocalizationTextQuery/Dependencies`。程序集和命名空间使用独立的 `LocalizationTextQuery.*` 前缀，只在 Editor 启用；无需安装 Unity CLI 或 Pipeline，也不需要另外下载 Roslyn。请完整导入，不要只复制 C# 文件。第三方许可证见包内 `THIRD-PARTY-NOTICES.md`。

## 扫描范围

- **指定目录**：扫描目录内的场景和 Prefab，包含可能未使用的资源。
- **启用场景及依赖**：以 Build Settings 的启用场景为入口，扫描序列化依赖。依赖关系不是运行时显示证明。
- **选中对象及子物体／选中资源**：在 Hierarchy 选中 Canvas2，就只扫描 Canvas2 自身和它的子物体，包含隐藏对象，不扩大到 Canvas1、整个场景或 Prefab 来源。支持未保存场景和多选；同时选中父子对象时自动去重。在 Project 中选择资源或目录时，仍扫描选中的资源及其序列化依赖。

Hierarchy 选中对象模式只读取组件，界面会禁用源码目录和代码分析。静态代码不能可靠按 Canvas 实例划分；需要代码赋值结果时，请使用目录／场景模式，或在 Project 中选择资源。工具不会为了分析代码而悄悄扩大选中的 Hierarchy 范围。未保存场景中的位置标识仅在当前编辑器会话有效，保存后重扫会生成正式位置标识。

依赖扫描不保证覆盖 Resources、Addressables、AssetBundle 或服务器路径加载的资源。这些资源应单独选目录扫描。

C# 赋值结果按“资源／源码目录”筛选，不受序列化依赖缩减，因为 C# 类型之间的调用关系不是资源引用。类型分析会读取所属程序集的其它源码来理解别名、继承和分部类，但不为范围外文件输出赋值结果。跳过 `Editor`、`Tests`、以 `~` 结尾的目录，以及不属于当前 Player 编译程序集的源码。类型分析错误、缺失依赖会报告警告，不退回全字符串扫描。

已经打开的场景读取当前内存状态；若有未保存修改，会在报告中说明，不强制保存。未加载的场景优先使用预览场景：Unity 2022 通过反射调用该版本未公开的 `OpenPreviewScene`，Unity 6 使用公开接口；其他缺少该接口的版本退回附加加载、扫描后关闭且不保存，并写明兼容路径警告。未保存的空场景可能阻止这种退回路径，但不会被工具强行保存或关闭。场景加载仍可能触发项目本身的编辑器回调或 ExecuteAlways 脚本，这是原生场景加载机制的限制。

## Excel 内容

- **翻译候选清单**：只包含勾选收录的记录；按完全相同的原文、人工 Key、接入方式暂时汇总。附带待填写译文列。
- **使用位置与待确认项**：包含所有位置和候选，保留排除原因、GlobalObjectId、资源 GUID、Prefab 来源、组件类型、字段和代码行号。
- **扫描说明**：包含范围、是否取消、扫描警告和覆盖边界。

原文保留前后空格、换行、富文本和大小写，所有单元格以字符串写入，避免把 `=...` 识别成公式。超过 Excel 单元格长度限制时明确拒绝导出，不截断原文；可以使用 JSON 保存。

同一句话出现在场景、Prefab、Prefab Variant 中可能有多处位置，这是来源追踪信息，不是重复删除失败。相同原文的汇总只是整理便利，不能证明语境相同。需要不同译文时填写不同 Key，并使用 SDK 能区分 Key 的接入方式；单纯按原文匹配的静态 SDK 无法区分完全相同原文的不同语境。

`group_...` 是报告内的原文分组标识，**不是 SDK Key**。工具不会按中文哈希自动生成 SDK Key。相同非空人工 Key 对应不同原文时，Excel 导出会拒绝并指出冲突。

导出的是扫描快照，不会读取已有 Excel 或保留其中编辑过的译文。首次交付后请另存翻译工作文件，不要用下一次扫描覆盖翻译文件。Excel 回读、译文合并和 SDK 特定格式输出属于后续阶段。

## 人工记录与重扫

收录状态、人工 Key、接入方式和备注保存在 `ProjectSettings/LocalizationTextQueryReview.json`，适合随项目纳入版本管理。它不是运行时语言表。

组件优先通过对象 GlobalObjectId 和属性路径匹配。相同位置原文变化时保留 Key 和备注，取消自动收录并标记复核。失去对象标识时会使用层级回退标识并说明；这种标识可能因重命名、移动或组件顺序变化而失效。代码记录包含赋值位置、表达式和分支序号，因此增删代码可能产生新候选，不会冒险把旧 Key 自动分配给别的赋值。

TMP 转旧版 Text 会替换组件并改变组件标识。后续迁移阶段必须另外保存旧组件→新组件的映射，修复可兼容引用，并处理脚本字段类型、UnityEvent、动画绑定和效果差异。输入框和下拉框不参与这条迁移流程。当前查询记录不能替代引用修复，也不保证现有 TMP 迁移工具能保留所有引用。

## 后续接入规划

1. 当前：查询来源、人工筛选、Excel 清单和位置追踪。
2. 文案定稿：确认 SDK 的原文匹配规则、参数语法和语言文件格式；处理拼接句和同文案不同语境；实现译文增量合并。
3. 独立 TMP 迁移：迁移前做引用审计，输出组件映射，验证脚本引用和排版；迁移后重扫并关联清单。
4. SDK 适配：静态文案挂载公司脚本；动态文案通过项目明确的文本变更入口调用按 Key API，避免把翻译后的赋值再次触发翻译形成循环。
5. 运行时补漏：覆盖语言切换、动态占位参数、缺失 Key、字体和长度问题。

旧版 `Text` 没有可直接等同于公司 SDK“文本内容已改变”的通用事件。动态监听的具体挂接方式，需查明公司 SDK 的事件或项目自己的赋值入口后再实现。

本版只保留 Text/TMP 组件和代码文本赋值两种来源。TextMesh、IMGUI、UI Toolkit/UXML、独立配置字段、图片中文字和服务器返回内容不直接采集，也不记录运行时实际显示过的内容。
